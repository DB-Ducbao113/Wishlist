## 2. Bugs found

### P0 — none

No data loss, no cross-account leakage, no unrecoverable state. The M1 session
guards from V16 still hold (proved again by `SESSION-10` / `SESSION-11`).

### P1 — fixed in F1

**P1-1 · KPI was computed from the filtered list, not the collection**

`render()` derived the three KPI values from `visibleItems()`, so search, status /
priority / category filters and sorting silently rewrote every total. `#sumCount`
reported the visible count instead of `items.length`.

Measured before → after, same 50-item fixture (`kpi-before.json` / `kpi-after.json`):

| State | Before (`562a62f`) | After (F1) |
| --- | --- | --- |
| no filter | `4.775.000 ₫` · `1.500.000 ₫` · `50 món` | `4.775.000 ₫` · `1.500.000 ₫` · `50 món` |
| `#fStatus = wish` | `1.512.000 ₫` · `0 ₫` · `12 món` | `4.775.000 ₫` · `1.500.000 ₫` · `50 món` |
| `#q = "Món 1"` | `901.000 ₫` · `345.000 ₫` · `11 món` | `4.775.000 ₫` · `1.500.000 ₫` · `50 món` |

_Fix:_ added `computeMetrics()` with `globalMetrics()` / `filteredMetrics()`;
`render()` now feeds the cards from `globalMetrics()` and only the
“Đang hiển thị …” line from `filteredMetrics()`.

**P1-2 · KPI labels described spending that is not recorded**

Card 1 was labelled “Còn phải chi” and card 2 “Đã chi”, which reads as real
spending even though no actual paid amount is stored anywhere — the figure is the
item's list price.

_Fix:_ card 1 → **“Giá trị chưa mua”**, card 2 → **“Giá trị đã sở hữu”** with the
explicit description “Tổng giá ghi nhận của món đã mua — chưa phải chi tiêu thực
tế”. Card 3 → “Bộ sưu tập” / “Tổng số món trong bộ sưu tập”.

## 6. Exact work list for F2 — Purchase Flow

Ordered, and each item names the file and the F1 artefact it builds on.

1. **Data model — record the real purchase.** In `wishlist.html` add optional item
   fields `paidAmount` (integer, ≥ 0), `purchasedAt` (epoch ms), `store`

   existing item valid without them. Add them to the add/edit form as a
   collapsible “Chi tiết mua hàng” group that only appears once
   `#fStatus2 === "purchased"`.
2. **Extend the metric contract.** In `computeMetrics()` add
   `recordedValue` (= today's `ownedValue`), `actualValue` (Σ `paidAmount` where
   present), `unpricedOwnedCount` (purchased items with no `paidAmount`), and
   `savings = recordedValue - actualValue` for the priced subset. Keep every
   existing field name so F1 tests keep passing.
3. **Purchase flow UI.** `markPurchased(id)` opens a small capture dialog
   (“Bạn đã trả bao nhiêu?”) instead of silently flipping the status. Skip the
   dialog when the user pressed the button twice, and always allow “Bỏ qua”
   which keeps `ownedValue` semantics identical to F1.
4. **KPI card 2 gets an honest split.** Card 2 shows `actualValue` when every
   owned item is priced, otherwise shows `recordedValue` plus the caption
   “{unpricedOwnedCount} món chưa ghi giá mua”. Never mix the two into one number.
5. **`undoPurchased()` must clear `paidAmount` / `purchasedAt` / `store`** (or
   move them to an `undoBackup`), otherwise an undo followed by a re-purchase
   silently reports a stale paid amount. This is the highest-risk step in F2 —
   write the test first.
6. **Status Distribution** — build per `dashboard-foundation.md` §4.3 using
   `globalMetrics().totalCount` as the denominator; add a `dv-dist` test that
   proves the counts ignore `visibleItems()`.
7. **Priority Widget** — §4.5. Must filter the collection only, leaving every KPI
   untouched (assert with the same `baseline` technique F1 uses).
8. **Category Breakdown** — §4.4, including the “Chưa phân loại” bucket and the
   6-row + “Khác” cap.
9. **Quick Actions** — §4.6, reusing `openForm(null)`, `#btnClearFilter`,
   `exportJson` and `importJson` verbatim.
10. **Export/import compatibility.** `exportJson()` must include the new fields;
    `importJson()` must accept old files that lack them (`normalizeItem()`
    already defaults missing keys). Add a round-trip test: export → import →
    metrics identical.
11. **Migration guard.** Items that were marked purchased *before* F2 have no
    `paidAmount`. `unpricedOwnedCount` must surface them and the UI must never
